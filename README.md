# Смысловой переключатель: few-shot классификация по скрытому правилу

Эпизодическая бинарная классификация русских текстов. Правило разметки скрыто
и меняется от эпизода к эпизоду, а модель должна вывести его из нескольких
размеченных примеров.

## Задача

Каждый эпизод состоит из:

- **8 размеченных сообщений (support)**: четыре с меткой `1` и четыре с меткой `0`;
- **4 сообщений (queries)**, для которых нужно предсказать метки.

Метки задаёт скрытое бинарное правило, например "сообщение про погоду",
"это вопрос" или "тон негативный". **Правило своё в каждом эпизоде**, поэтому одно
и то же сообщение в разных эпизодах получает разные метки. Классификатор, который
выдаёт метку по одному тексту, здесь бесполезен: правило нужно извлекать из
support самого эпизода.

Метрика **Episode Exact Match**: эпизод засчитывается, только если
верны все четыре ответа. Случайное угадывание даёт 1/16, около 6%.

Данные хранятся в JSONL, одна строка на эпизод. У queries в train есть `label`,
во входных данных для предсказания его нет. На каждый query пишется строка
предсказания, где `label` равен `1` тогда и только тогда, когда `probability >= 0.5`.

```text
эпизод:       {"episode_id": "ep1", "support": [{"example_id": "s1", "text": "...", "label": 1}, ...], "queries": [{"query_id": "q1", "text": "...", "label": 0}, ...]}
предсказание: {"episode_id": "ep1", "query_id": "q1", "label": 1, "probability": 0.73}
```

Ограничения задачи:

- замороженная [`cointegrated/rubert-tiny2`](https://huggingface.co/cointegrated/rubert-tiny2), её веса менять нельзя;
- только CPU, 2 потока, 4 ГБ памяти, 25 минут на обучение и предсказание вместе;
- не больше 150 000 обучаемых параметров;
- модель обучается с нуля на закрытом train, который при разработке недоступен;
- во время предсказания нельзя обучаться и использовать градиенты.

## Решение

```
текст -> rubert-tiny2 (заморожена) -> CLS + среднее по токенам с 4 уровней (2496 чисел)
      -> стандартизация -> обучаемая проекция из 2496 в 48 чисел
      -> "переключатель" по support эпизода -> логиты 4 queries
      -> совместное решение по 4 queries -> метки и вероятности
```

### Переключатель: support-gated diagonal LDA

Для каждого эпизода по 8 примерам support в 48-мерном пространстве считаются:

```
μ⁺, μ⁻    центры классов 1 и 0
m         середина между центрами
σ²ₖ       разброс внутри классов по признаку k, смешанный с выученным
          "типичным" разбросом (shrinkage), потому что примеров всего 8
tₖ        = |μ⁺ₖ − μ⁻ₖ| / σₖ            насколько надёжно признак разделяет классы
gₖ        = sigmoid(a·tₖ + b)           гейт: выключает признаки, различающиеся случайно

score(q)  = Σₖ gₖ · (μ⁺ₖ − μ⁻ₖ) / σ²ₖ · (qₖ − mₖ)
```

Без гейта это логарифм отношения правдоподобий двух нормальных классов с
диагональной ковариацией, то есть линейный дискриминант Фишера. Гейт
пересчитывается в каждом эпизоде и оставляет только признаки, по которым
support действительно разделён. Так модель "переключается" на правило эпизода.

Подстройка под эпизод сводится к готовой формуле без градиентного спуска,
поэтому при предсказании ничего не обучается. От обучения зависят только проекция,
выученный разброс и пять скаляров (a, b, доля shrinkage, масштаб, сдвиг):
**119 909 параметров**.

### Мета-обучение

Модель обучается на эпизодах из train, решая ту же задачу, что и на тесте.
Сначала эмбеддинги всех уникальных текстов один раз кэшируются. Затем на каждом шаге:

- 12 размеченных сообщений эпизода заново делятся на support 4+4 и 4 queries;
- в половине эпизодов метки `0`/`1` меняются местами, чтобы модель была симметрична;
- 20% эпизодов составляют псевдоправила вида "в тексте есть слово X",
  построенные по текстам train. Они нужны для устойчивости к правилам, которых не было в обучении.

Число шагов обучения ограничено снизу, поэтому даже запуск с
`--epochs 1 --batch-size 1` даёт обученный адаптер.

### Совместное решение по четырём queries

На train запоминается распределение числа положительных queries в эпизоде.
При предсказании из 16 комбинаций меток выбирается самая вероятная с учётом
этого распределения. Для exact match это подходит лучше, чем четыре независимых
порога. Вероятностями в ответе служат маргиналы этой совместной модели,
согласованные с выбранными метками.

## Результаты на прокси-данных

Настоящий train при разработке недоступен, поэтому подходы сравнивались
на двух самодельных корпусах (оба лежат в `dev/`):

- **A**: шаблонные предложения с точно известными атрибутами
  (категория объекта, цвет, размер, время, отрицание, вопрос и т.д.);
- **B**: 1250 естественных сообщений, написанных LLM по заданным атрибутам
  (тема, тональность, форма, время, лицо, наличие чисел и т.д.) и проверенных
  слепой переразметкой.

Train и test не пересекаются по текстам. Новыми правилами считаются
атрибуты, которые вообще не встречались как правила в train.

| Корпус и распределение queries | Правила из train | Новые правила |
|---|---|---|
| A, queries 2+2 | 0,98 | 0,19 |
| A, queries случайно | 0,94 | 0,14 |
| B, queries 2+2 | 0,80 | 0,28 |
| B, queries случайно | 0,56 | 0,11 |

Для сравнения: случайное угадывание даёт около 0,06, а сравнение с центрами
классов без обучения около 0,2.

Слабое место решения: правила, которых не было в train. На них выученная
проекция переносится плохо.

Время и память при 4000 train- и 1000 test-эпизодах с длинными текстами
(2 потока CPU): обучение около 4,5 мин и 2 ГБ, предсказание около 22 с.

## Как запустить

1. Окружение (Python 3.10+) и модель:

   ```bash
   python -m venv .venv
   .venv/bin/pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cpu  # CPU-сборка, без CUDA
   .venv/bin/pip install -r requirements.txt
   ./download_model.sh   # rubert-tiny2 в assets/model, около 113 МБ
   ```

2. Быстрый старт на прокси-корпусе B, он лежит в репозитории:

   ```bash
   .venv/bin/python dev/episodes.py --corpus b --query-mode balanced   # эпизоды в runs/proxy/b_balanced
   .venv/bin/python -m hidden_rule.train --train runs/proxy/b_balanced/train.jsonl --adapter runs/adapter.safetensors
   .venv/bin/python -m hidden_rule.predict --data runs/proxy/b_balanced/test_seen.jsonl \
       --adapter runs/adapter.safetensors --output runs/predictions.jsonl
   .venv/bin/python dev/evaluate.py runs/proxy/b_balanced/test_seen.jsonl \
       runs/proxy/b_balanced/test_seen.labels.jsonl runs/predictions.jsonl
   ```

   Свои данные подаются так же: `--train` и `--data` принимают JSONL в формате
   из раздела "Задача". Дополнительные параметры обучения: `--epochs`,
   `--batch-size`, `--learning-rate`, `--seed`, `--max-episodes`; у обеих команд
   есть `--model-dir` (по умолчанию `assets/model`) и `--threads` (по умолчанию 2).

3. Тесты (не требуют модели):

   ```bash
   .venv/bin/python -m pytest -q tests
   ```

4. Эксперименты на прокси-данных:

   ```bash
   .venv/bin/python dev/make_proxy_a.py                         # корпус A
   .venv/bin/python dev/episodes.py --corpus a --query-mode bern  # эпизоды в runs/proxy/a_bern
   dev/run_e2e.sh a_bern                                         # train, predict и оценка
   (cd dev && ../.venv/bin/python heads.py a_bern a gated d=48 feats=all)  # быстрые эксперименты на кэше
   ```

## Структура

```
download_model.sh   загрузка rubert-tiny2 с Hugging Face с проверкой SHA-256
hidden_rule/
  backbone.py   замороженная rubert-tiny2 из локальной папки
  data.py       чтение эпизодов с проверкой формата, запись предсказаний
  features.py   замороженные признаки: CLS + среднее по токенам со всех уровней
  model.py      EpisodeClassifier (переключатель) и совместное декодирование
  train.py      кэширование признаков и мета-обучение
  predict.py    только инференс
tests/          быстрые тесты формата данных и модели
dev/
  make_proxy_a.py, make_proxy_b_specs.py, merge_proxy_b.py   прокси-корпуса
  proxy_b/      спецификации, тексты (gen_*), слепая переразметка (ver_*), корпус
  episodes.py   сборка эпизодов в JSONL, разбиение на известные и новые правила
  features.py, harness.py, baselines.py, heads.py   исследовательский стенд на кэше признаков
  evaluate.py   строгая проверка формата и Episode Exact Match
  run_e2e.sh    полный прогон train, predict и оценки с замером времени и памяти
```

## Что не входит в репозиторий

- **Веса rubert-tiny2**: 113 МБ, больше лимита GitHub. Модель доступна на Hugging Face
  под лицензией MIT; `download_model.sh` скачивает ревизию
  `e8ed3b0c8bbf4fb6984c3de043bf7d2f4e5969ae` и проверяет SHA-256 каждого файла.
- **Корпус A**: детерминированно пересобирается `dev/make_proxy_a.py`.
